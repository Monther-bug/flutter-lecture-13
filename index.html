Idea 1 · Use what we know

Lifting state up

  • ProductsPageowns _cartCount (lifted up here)
    • appBar:AppBar
      • CartBadge(count)↓ data goes down
    • body:ProductList(onAdd)↓ callback goes down
      • ProductTile(onAdd)↑ event goes up: onAdd() → setState
  1. Find the closest common parent of every widget that needs the data
  2. Move the data and setState into that parent
  3. Pass data down as constructor parameters
  4. Pass callbacks down; children call them to send events up
A callback is just a function we hand to a child, like onPressed in Lecture 07.

Built into Flutter · no package

Flutter's own tool: ValueNotifier + ValueListenableBuilder

lib/cart_count.dart · lib/cart_badge.dart
// cart_count.dart: one place for the data
final ValueNotifier<int> cartCount = ValueNotifier<int>(0);

// Change it from anywhere: cartCount.value++;
// Listen to it inside build() (cart_badge.dart):
ValueListenableBuilder<int>(
  valueListenable: cartCount,
  builder: (context, count, child) {
    return Badge.count(
      count: count,
      isLabelVisible: count > 0,
      child: const Icon(Icons.shopping_cart),
    );
  },
)
1ValueNotifier: one placeholds one value and notifies listeners when .value changes
2Change it from anywherecartCount.value++; in any button, on any page
3ValueListenableBuilder: listenre-runs only its builder when the value changes
A top-level (global) variable is fine for this demo. In Lecture 14, Provider gives us a cleaner way to share it.

Mobile App Development · Lecture 13

These numbers are real. We ran both Mini Shop versions in a Flutter test and counted every widget whose build() ran after one "add". v1: the 8 widgets we wrote plus everything inside them (each ListTile and IconButton is made of many small widgets), 366 in total. v2: 7.

Is setState bad? No. At 60 frames per second Flutter has about 16 ms for each frame, and a phone rebuilds a few hundred widgets quickly. The cost grows with the page: long lists, big screens and animations are where extra rebuilds hurt.

Students can see the same counts themselves: DevTools, Performance page, "Track widget build counts", then "Rebuild Stats".

Wrap-up

Summary

Today you learned

  • State = data that changes and affects the screen; UI = f(state)
  • Your screen is a widget tree of parents and children
  • setState rebuilds its widget and everything inside it (71 widgets for one tap); const widgets are skipped
  • Local state → setState; shared state → one shared place
  • ValueNotifier + ValueListenableBuilder: only listeners rebuild (366 → 7)
  • Next lecture: Provider
